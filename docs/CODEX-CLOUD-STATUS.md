# ECC в облачной сессии Codex

## Что подготовлено

- Рабочее окружение остаётся в существующем облаке Codex.
- Форк: `alexpostnik/ECC`, ветка `work/cloud-setup`.
- Подготовлен и сохранён приватный пакет **ECC Cloud** версии `0.1.0`.
- Исходная версия пакета: коммит `8a7449c08694b57a31a0974fa390ec5c3c5b55f1`.
- Пакет предоставляет один входной навык `ecc` и оригинальные материалы ECC:
  311 навыков, 71 инструкцию для агентов и 122 файла правил.
- Нативные hooks, MCP-серверы и автоматический сбор памяти этим пакетом
  не включаются. Применимость каждого workflow зависит от инструментов беседы.

[Инструкция и воспроизводимая сборка](../plugins/ecc-cloud/README.md).

## Проверки

- 18 тестов упаковки проходят; покрытие исполняемых строк сборщика — 146/154
  (94,8%, стандартный Python `trace`, без измерения покрытия ветвлений).
- Сверены все 807 исходных файлов архива и их SHA-256.
- После сохранения приватного плагина через API владельца побайтно проверены
  entry skill, runtime, provenance, catalog, coding-standards и verification-loop.
- Сервис добавляет compatibility manifest и нормализует сведения о владельце
  в manifest. Проверенные исходные навыки и references сохраняются без изменений.
- Проверки Markdown и Git diff проходят; выполнено независимое ревью.

После добавления плагина пользователем проверочный агент с обновлённым контекстом
обнаружил `ecc-cloud:ecc` через штатный cloud skill discovery. Через полученный
package/resource он прочитал входной навык, runtime, source, catalog, исходные
code-reviewer, coding-standards и verification-loop. По verification-loop выполнена
практическая проверка сборщика: все 18 тестов прошли с exit code 0. Таким образом,
подключение и применение навыка подтверждены отдельно от API владельца плагина.

Основной уже выполняющийся контекст той же беседы продолжает возвращать пустые
списки cloud/executor skills и `skill package is not available` при чтении этого
пакета. Это ограничивает доступность навыка по контекстам; успешная проверка
проверочного агента не означает обновления основного контекста. На скриншоте
пользователя ECC выбран в редакторе нового задания Work. Для самостоятельной
работы следует отправить задание с выбранным плагином и проверить его discovery.

## Журнал ограничений

| Ограничение | Подтверждение | Следующее действие |
| --- | --- | --- |
| Native профиль Codex защищён от записи | CLI 0.159.2 есть, активный CODEX_HOME read-only | Использовать поддерживаемый host plugin surface; native install требует разрешённого профиля |
| Доступность ECC Cloud различается между контекстами | Проверочный агент обнаружил и применил навык; основной контекст возвращает пустой список и отклоняет чтение | Документировать необходимость проверки discovery в рабочем контексте после подключения плагина |
| Codex-инструкции отстают от canonical | Отличия verification-loop и описания MCP подтверждены чтением файлов | Отдельное исправление копий и документации |
| Guided setup проверяет официальный origin | Код выдаёт MARKETPLACE_COLLISION для другого источника | Уточнить отдельный supported fork workflow, сохранив provenance checks |
| GitHub Issues выключены, интеграция не может включить | GET has_issues=false; PATCH 403; POST issue 410 | Владелец включает General → Features → Issues, затем публикуются подготовленные задачи |
